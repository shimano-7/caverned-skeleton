# Stock Lens / caverned-skeleton

iPhoneのSafariで使える、日本株・米国株の日足CSV分析Webアプリです。外部ライブラリ・APIキー・ビルド作業は不要です。

## 使い方

1. 起動すると架空の日本株サンプル180本を表示します。「米国株」でドル表示の架空サンプルに切り替えられます。実在銘柄・実際の市場データではありません。
2. 「ひな形をダウンロード」で、サンプルデータ入りのCSVを保存できます。
3. 「CSVを取り込む」でiPhoneの「ファイル」からCSVを選びます。銘柄名は編集できます。市場ボタンで円・ドル表示を選択してください。為替換算はしません。
4. 90本・180本・全期間の表示切り替え、チャートのタップで日付・終値・移動平均・出来高を確認できます。
5. クロスの最新発生日と全履歴、買い・待ち・見送りの参考判定を表示します。

データはブラウザ内で処理され、サーバーに送信しません。保存機能はなく、再読み込みすると消えます。リアルタイム株価取得はありません。

## CSV形式

UTF-8（BOM可）、1ファイル1銘柄、日足、最大5MB・10,000行。

```csv
date,close,volume
2026-01-05,2850,1200000
2026-01-06,2875,1350000
```

- ヘッダーは `date,close,volume` または `日付,終値,出来高`。追加列や列順変更も可。
- 日付は `YYYY-MM-DD` または `YYYY/MM/DD`。昇順に並べ直します。重複日、不正日付、空欄、不正数値はエラーです。
- 終値は正数、出来高は0以上の整数。桁区切り付き数値は `"1,200"` と引用してください。
- 最低1本で表示、25本で25日線、75本で75日線、76本からクロス検出が可能です。
- 移動平均は取り込んだ日足の25本・75本の単純平均。表示期間を変更しても計算には全取り込みデータを使います。
- 休日・欠損日の補完はしません。連続した営業日データを用意してください。株式分割や配当を考慮する場合は調整済み終値を使用してください。

## 参考判定

- 買い：25日線が75日線より上、かつ終値が25日線より上。
- 見送り：25日線が75日線より下、かつ終値が25日線より下。
- 待ち：それ以外、または75本未満。
- ゴールデンクロス：前日の25日線が75日線以下、当日は上。
- デッドクロス：前日の25日線が75日線以上、当日は下。

出来高は表示用で、参考判定には含みません。履歴の最新クロスは最新日の売買指示ではありません。投資助言・利益保証ではなく、業績・ニュース等も含めた投資判断の参考情報です。

## ローカル起動・テスト

Node.js 24とPython 3を使用。依存パッケージのインストールは不要です。

```sh
cd /workspace/caverned-skeleton
npm test
npm start
```

開発PCではポート8000でHTTPサーバーが動きます。ES Modulesを使うため、HTMLをファイルとして直接開かずHTTP経由で利用してください。クラウド環境のループバックアドレスはiPhoneからアクセスできないため、以下の公開手順を利用してください。

`npm test` は移動平均・判定・両クロス・横ばい・CSV正常系/異常系・日米サンプルの7テストを実行します。

ブラウザ操作テストは `tests/browser.cjs`。Playwrightを別ディレクトリに入れ、サーバーを起動した状態で実行できます。

```sh
npm install --prefix /tmp/stock-lens-browser --no-package-lock playwright
NODE_PATH=/tmp/stock-lens-browser/node_modules node tests/browser.cjs
```

Chromiumは `/usr/bin/chromium` を使用。別パスなら `CHROMIUM_PATH` 環境変数で指定できます。390×844のモバイル相当画面と1280×900で検証します。これは実機Safariのテストではありません。

## iPhone Safariで開く公開方法（GitHub Pages）

公開用の `.github/workflows/pages.yml` を用意しています。公開の成否はGitHub Actionsの実行結果で確認してください。

1. この変更を `shimano-7/caverned-skeleton` の `main` ブランチにコミット・pushします。
2. GitHubのリポジトリで **Settings → Pages → Build and deployment → Source → GitHub Actions** を選択します。権限やプランによってPagesを使えない場合は、管理者の設定または対応プランが必要です。
3. **Actions → Deploy Stock Lens to GitHub Pages → Run workflow** を実行します。設定後のmainへのpushでも自動実行されます。
4. テストとデプロイが成功したら、Actionsの `github-pages` に表示される公開URLを確認します。標準URLは `https://shimano-7.github.io/caverned-skeleton/` です（公開前はアクセスできません）。
5. iPhoneのSafariでそのHTTPS URLを開きます。「サンプルを読み込む」、市場切り替え、グラフのタップを確認します。
6. 「ひな形をダウンロード」で「ファイル」にCSVを保存し、「CSVを取り込む」から選んで実機での読み込みを確認します。
7. 必要ならSafariの共有メニューから「ホーム画面に追加」できます。オフライン動作は提供していません。

公開されるファイルはHTML・CSS・JSだけです。ユーザーが選ぶCSVや認証情報はデプロイしません。

## 日本株の自動発掘（追加機能）

トップ画面は実データ専用です。既存の日米CSV分析と架空サンプルは「CSV分析・架空サンプルを開く」の中に残しています。架空データはランキングに使用しません。米国株・韓国株の自動発掘は未対応で、画面に準備中と表示します。

### 実データの接続設定

採用アダプターはJPXの **J-Quants API v2** です。`x-api-key` 認証で `/equities/master`、`/equities/bars/daily`、`/fins/summary` を使用します。API契約は直近株価と比較可能な2期分の通期財務が取得できる必要があります。遅延データしか利用できないプランでは鮮度基準によりランキング対象外になります。

**重要：本環境にはAPIキーがなく、公式仕様サイトも通信制限で参照できなかったため、現行v2 APIとの実接続・契約プランごとのフィールド互換性は未検証です。** 形式が違う場合は空ランキングと理由を出し、推定値を生成しません。APIキー設定後にまず更新結果を検証してください。

iPhoneでの設定：

1. GitHubのリポジトリ → **Settings → Secrets and variables → Actions → New repository secret**。
2. Nameは `JQUANTS_API_KEY`。SecretにJ-Quantsで取得したAPIキーを入力して保存。キーはチャットやソースに書かないでください。
3. **Settings → Pages → Source → GitHub Actions**。
4. **Actions → Deploy Stock Lens to GitHub Pages → Run workflow → main → Run workflow**。
5. 成功したら `https://shimano-7.github.io/caverned-skeleton/` をSafariで確認します。

APIキーを使うのはGitHub Actionsの更新処理のみで、静的サイトに出力しません。公開アーティファクトに含めるのは画面・計算モジュールと取得した市場データJSONです。**市場データそのものは公開されるため、公開再配信が許可された契約・利用条件を確認してください。個人向けAPIの契約が公開再配信を許可するとは限りません。** キーを隠すこととデータの再配信許可は別です。

### 取得対象・更新・制約

- 初期対象は東証プライムの銘柄コード昇順10銘柄。全日本株からのランキングではありません。画面に母集団・試行数・評価可能数を表示します。
- `.github/workflows/pages.yml` の `SCREEN_LIMIT` は5〜100に変更可能。APIのレート・契約上限と更新時間を確認して拡大してください。1銘柄ずつ取得し、429時は待って再試行します。
- 平日19:30 JSTに更新予定（GitHub Actionsの遅延あり）、手動実行も可能。更新処理は最新レスポンスのみでJSONを再生成し、失敗時は過去のおすすめを引き継ぎません。
- 更新から36時間超、価格が7日超前、通期決算開示が460日超前、財務欠損、76本未満の価格は非表示または対象外です。休場が長いとランキングも非表示になります。
- APIキーなしでもデプロイは成功させ、画面では「取得できない」と表示します。**Actionsの緑チェックは市場データ取得の成功を意味しません。** ログの `Market data: ok` と画面の取得元・更新日時を確認してください。
- 株価・出来高は調整済み、PER・PBR・配当利回りの計算には未調整終値を使用。財務は直近通期実績（予想・TTMではない）。ROEは2期の平均自己資本を使用します。開示後の分割等によるEPS/BPSの変化は未調整なので注意が必要です。
- 最新クロスは取得期間内の最後の交差。RSIは14期間のWilder方式。出来高比は当日と直前20本平均の比較です。
- 22件のユニットテストで既存機能・財務・ランキング・欠損除外・RSIを検証しています。実データ接続と実機SafariはAPIキーと公開環境で別途検証が必要です。

### API処理時間の上限（長時間実行対策）

- 既定20銘柄、APIリクエスト間隔1.2秒。進捗は銘柄ごとに開始・成功・対象外を表示します。
- 1回の通信は本文JSONの読み取りも含め15秒。429・5xx・通信障害の再試行は1回だけ、待機15秒。最終失敗後の追加待機はありません。
- 全体は5分。ページングは各エンドポイント10ページ・10万行まで、同一キー循環を検出。
- 400/401/403/404・未対応形式・429再試行上限は即時中止。銘柄ごとの失敗が5件続いても中止します。
- 中止時は空のランキングと安全な理由をJSONに保存します。部分取得ランキングを完全な結果として公開しません。APIレスポンス本文・キー・ヘッダー・外部例外の生メッセージをログや公開JSONに出力しません。
- Actionsは更新ステップ6分・ジョブ15分を最終上限とします。強制タイムアウト時はデプロイされず、既存公開データは36時間で画面から非表示になります。
- 元の処理は100銘柄、429ごとに合計150秒の待機、全体上限なし・中間ログなしでした。実際の実行#4の原因はActionsログで別途確認が必要です。

### 429対策と再利用（最新の動作）

公式クライアントの[レートリミット説明](https://github.com/J-Quants/jquants-api-client-python/blob/4a6ab360dbd43e763595f7ad362e749a25d6439d/README.md#レートリミット)では、上限はプランごと、超過時は429とされています。[公式プラン別一覧](https://jpx-jquants.com/spec/rate-limits)はこの環境の通信制限で直接確認できていません。利用中のプラン・他アプリと共有する呼び出し量も確認してください。最初のmaster取得で429の場合、本実行前から利用枠が消費されている可能性があります。

以下が上の「長時間実行対策」に代わる現在の値です。

- 初期対象は10銘柄。リクエスト間隔13秒（約4.6回/分）を全エンドポイント・ページング・再試行で共有します。これは保守的な既定値で、契約プランの上限を保証する数値ではありません。
- 429の再試行は最大2回。Retry-Afterの秒数・HTTP日付を尊重し、少なくとも60秒→120秒の指数バックオフと最大1秒のジッターを使います。上限到達時もクールダウンを保存し、次の実行で引き継ぎます。
- 全体10分、Actions更新ステップ11分、ジョブ20分。サーバーの待機指示が残り時間より長ければ、早く再試行せず時間切れで終了します。
- `.market-cache/`に成功したAPI応答のデータ配列のみを保存。masterは7日、財務は24時間、価格は12時間再利用。成功ページの途中ではなく、各エンドポイントの全ページ取得成功時に確定します。後続銘柄の失敗でも確定済みデータは保持されます。
- Actions cacheで実行間に復元・保存します。公開アーティファクトやGitにはキャッシュを含めません。キー・ヘッダー・認証エラー本文は保存しません。GitHubのキャッシュ削除・容量制限によって再取得が必要になることがあります。
- 更新失敗時、以前取得した実データランキングが36時間以内・株価7日以内なら再利用。**取得時刻を新しい時刻に書き換えず**、更新失敗の警告と最終試行時刻を表示します。期限切れ・未取得ならランキングは表示しません。キャッシュはAPIキー未設定の過去実行からデータを復元するものではなく、最初の成功取得が必要です。
- 更新処理の生成日時とは別に、銘柄ごとに実際の株価取得・財務取得日時も表示します。
- 31件のテストでRetry-After、待機引継ぎ、キャッシュ復元・TTL・失敗時保持と従来の機能を確認しています。実APIの現在の利用枠はテストしていません。

### キャッシュだけで除外理由を診断する（現在のActions設定）

現在のPagesワークフローは `CACHE_ONLY=true` 固定です。通常のpush・手動実行・定期実行のいずれもJ-Quantsにアクセスせず、Actions cacheの保存済みデータを再判定します。APIキーもこのステップには渡しません。データ更新を再開する場合は、別途明示的にワークフロー設定を戻す必要があります。

ローカルでは `npm run diagnose:cache`。`MARKET_CACHE_DIR` で保存先を指定できます。診断時はキャッシュのTTLを過ぎていても読み取りますが、株価・財務の鮮度基準は従来どおり適用して古いデータを除外します。取得日時は保存した値を使い、再判定日時と区別します。

各銘柄に次を記録し、Actionsログとアプリの「データ診断」に表示します。

- 株価データ：本数、最終日、欠損・不正・鮮度。
- 財務データ：比較できる通期決算の不足、計算に必要な未調整終値の不足、PER・PBR・ROE・成長率・配当利回りの欠損。
- 25日線・75日線：それぞれ利用可能か、必要本数と実際の本数、計算不可。
- 対象・評価可能・除外銘柄数と、項目別の不足・不正等の件数。項目別件数は同じ銘柄を重複計上します。

ランキング0件でも除外理由を破棄せず `data/japan.json` に保存します。masterがなければ価格・財務キャッシュ内の銘柄コードから診断し、すべて空なら「キャッシュなし」と表示します。キャッシュがGitHub側で削除・未保存の場合は復元できませんが、自動でAPI取得には切り替えません。

テストは38件。キャッシュ専用CLIに通信禁止のfetchを注入し、追加API呼び出しがないことも検証しています。

### 日本株の鮮度判定（取引日と取得日時を分離）

以前は `現在時刻 − 最終行の日付 > 7暦日` で株価を除外していました。取得日時・本数・移動平均の有無ではなく、株価の実際の取引日を評価する点は維持し、暦日差を取引所カレンダーでの比較に置き換えました。

- `priceFetchedAt` は通信・キャッシュ保存の時刻、`priceDate` / 診断の `lastDate` は価格行の取引日、`generatedAt` は分析・再判定時刻です。それぞれを別に表示し、取得時刻で株価日付を上書きしません。
- 日本時間で最後に取引を終えたJPX現物株の営業日を基準にします。土日、国民の祝日・振替休日・国民の休日、1月1〜3日、12月31日を除外。2024〜2027年を明示的に収録し、対応年外は判定不可としてランキングから除外します。
- 引けは2024年11月5日以降15:30、それ以前15:00。引け前は前営業日を基準とします。引け後に当日価格がなければ20:00までは「反映待ちの可能性」、以降は「未収録」と表示し、どちらもランキング対象外です。20:00はアプリの反映待ち表示用の時刻であり、プロバイダーの配信完了を保証する時刻ではありません。
- 最終終了取引日と価格日付が一致した場合のみ鮮度条件を満たします。不足する営業日数を数え、1営業日でも未収録なら最新扱いしません。判定基準を緩める修正ではありません。
- 対応カレンダーの出典：[JPX休業日](https://www.jpx.co.jp/corporate/about-jpx/calendar/index.html)、[内閣府国民の祝日](https://www8.cao.go.jp/chosei/shukujitsu/gaiyou.html)。臨時休場や新規祝日などの変更時は収録表の更新が必要です。
- GitHub Actionsログと画面には「基準取引日・保存データの実際の取引日・取得日時・不足営業日数」を表示します。最新の取得日時でも、価格日付が過去なら対象外です。データ配信プランの遅延、取得範囲、古いキャッシュ等の区別にはこの実日付とプロバイダー側の情報が必要です。
- 静的サイトを開いた時点でも価格日の鮮度を再検証し、新しい取引日終了後に古い上位銘柄を最新として表示しません。

この環境から公開JSONとActionsログへのアクセスは通信制限で拒否されるため、公開画面の208本の**実際の最終日付は未確認**です。休日計算の不備はコードで確認しましたが、それが当該データの除外理由の全てとは断定していません。2026年10月31日（土）の基準は2026年10月30日（金）。保存データがそれ以前なら、その不足は休日だけでは説明できません。

### 現行運用：J-Quants Freeの過去時点ランキング

**現在はFreeプラン・12週間遅延の過去データ分析として運用します。** 上記のリアルタイム鮮度による除外やキャッシュ専用Actionsの記述に代わり、以下を適用します。

- 各銘柄の実際の収録最終取引日を「データ基準日」として、25/75日線、RSI、出来高、財務指標を分析します。現在から古いことだけでは除外しません。現在の売買推奨・現時点のランキングではありません。
- 銘柄ごとに基準日が異なる場合があります。全銘柄が同一日時の比較とは限らないことを画面に明記します。
- 財務は基準日までに開示済みの通期情報のみ使用。財務の古さも基準日と比較します。基準日以降の開示情報を使って過去の評価を良くすることはしません。
- Free提供目安日は12週間前の取引日として別に表示し、実際の価格日付を書き換えません。提供目安より古い保存データも過去分析として表示でき、最新の提供範囲まで更新済みとは表示しません。
- Actionsは通常取得モードへ戻し、`JQUANTS_API_KEY` をGitHub Secretsから渡します。価格の取得終了日はFree提供目安日まで。毎分5回制限に対して13秒間隔を共有し、ページング・再試行も同じ制限に従います。429ではRetry-Afterとバックオフを尊重します。手動診断 `npm run diagnose:cache` は引き続き通信なしです。
- 取得失敗時、保存済みの生データをFreeモードで再分析して公開します。欠損・計算不可能な指標は引き続き除外し、データを捏造しません。
- 過去結果は生成から36時間で非表示にせず、古い再分析日時を警告します。株価の実際の日付・取得日時・再分析日時は分けて表示します。
- APIキーはコード、公開JSON、キャッシュ、ログに含めません。利用条件による市場データの再配信制限は別途確認が必要です。

51件のテストに加え、過去時点のランキングがモバイル画面で表示される操作テストを用意しています。テスト用データはブラウザの通信差し替え・一時ディレクトリのみで使用し、公開データへ混ぜません。
